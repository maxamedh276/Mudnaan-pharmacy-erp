# Excel imports for products, suppliers and customers

Each directory has an **Import Excel** button beside Add. Download its sample workbook,
replace the example rows in **Data**, and keep the template headers. For products, either barcode column can be omitted.
The **Instructions** sheet explains each field. Only **Data** is imported.

1. Upload an `.xlsx` workbook and select **Validate Excel**.
2. Correct the reported Excel row numbers and upload again if any row fails.
3. Once every row passes, select **Import all rows**. The server validates again against
   current database data before writing. A write failure rolls back the entire workbook.

Limits: 5 MB compressed, 32 MB expanded, 16 MB per ZIP member, 500 archive entries,
5,000 data rows, 40 columns, 120,000 cells. Completely blank rows are ignored. Partially
filled rows must satisfy all required fields. Only standard XLSX is supported, not XLS,
XLSM or CSV. Formulas in Data, external links, macros, embedded objects, unsafe XML,
duplicate/unknown/missing headers and malformed cell references are rejected.
Store phone numbers and barcodes as **Text** and re-enter values after formatting, so
Excel preserves leading zeros and plus signs. Numeric identifier cells are rejected.

## Record rules

Imports **create new records only**. They never update or silently skip existing records.
Names must be unique within the workbook and against non-deleted records of that type
(trimmed and case-insensitive). Non-empty product barcodes, or contact phones/emails,
must also be unique. Shared contact numbers therefore need correction before import.

Products require `name`, `category`, `unit`, `sell_price`, `reorder_level`, `stock_type`.
Use a complete existing active category path from **Categories**; categories are not
created automatically. Replace the category placeholders in the sample before uploading.
Units: `pcs`, `box`, `pack`, `kg`, `g`, `litre`, `ml`, `cup`.
Stock type: `sealed` or `non_sealed`.

- Sealed: base unit must be pieces, kg or litre. Require `package_unit`, positive
  `package_size`, non-negative `package_price`. A distinct `sealed_barcode` is optional.
  A box of pieces must contain a whole number of pieces. Reorder threshold counts sealed packages.
- `barcode` is the optional main barcode. Format both barcode columns as Text
  to preserve leading zeros. A barcode must be unique across both columns and product SKUs.
- Non-sealed: leave all package fields empty; reorder threshold uses base units.
- `default_sale_mode`: loose (default) or sealed; sealed requires package configuration.
- Optional `quantity_group`: existing active Selling Options group name matching the
  base unit. Blank means no quantity shortcuts. SKU is generated by the existing service.
- `opening_sealed`: whole unopened packages (zero for non-sealed).
- `opening_quantity`: already-opened or ordinary base-unit stock, up to 3 decimals.
- `opening_unit_cost`: required for positive opening stock. Cost per **sealed package**
  for sealed products; cost per **base unit** for ordinary products. Requires stock.adjust.
  Opening stock belongs to the signed-in user's branch and uses the existing inventory,
  package and premium accounting services, including the owner-capital offset.

Customers/suppliers require `name`; `phone`, `email`, `address` are optional. Email must
be valid when provided. Financial balances, debts and customer credit limits are excluded.

## Developer implementation

- Web routes: `GET web/imports/{products|suppliers|customers}/template` and
  `POST web/imports/{kind}` with multipart `workbook` and `action=validate|import`.
- Permissions: products.create, suppliers.manage, customers.manage respectively.
  Both routes and the service enforce the matching permission. Upload requires AJAX.
- `ImportWorkbookReader` reads only bounded ZIP/XML values with PHP ZipArchive and
  SimpleXML, supporting both shared/inline strings and prefixed/default OOXML namespaces.
  It never extracts files or evaluates workbook code. It requires the Data sheet.
- `WorkbookImportService` preloads reference and duplicate indexes, reports errors for
  every invalid row (first applicable error per row), and performs no writes in preflight.
  The internal `records` payload is removed before HTTP responses.
- Product and opening-stock preflight reuse the manual creation validators. Customer
  details validation is shared with the profile form. Supplier fields enforce DB lengths.
- On commit, a tenant-scoped MySQL advisory lock serializes these web imports, then an
  outer `FinancialTransaction` covers all record/stock/accounting writes. Nested domain
  transactions retain this outer atomic boundary. Manual form edits do not take this
  import lock; normal database constraints remain authoritative for competing writes.
- The session caches the most recent successful file hash/result per tenant, branch,
  kind and user, so a response retry cannot duplicate the same upload. Across sessions,
  existing-record validation prevents repeat imports. Refreshing the directory after
  success updates rows and summary totals together.
- The shared native dialog scrolls on small screens, keeps row errors visible, disables
  duplicate submissions while busy, uses text-only errors and the shared toaster.

## Deployment and database changes

**No new tables, columns, migrations or production SQL are required for this feature.**
It uses the existing product/inventory workflow schema and the configured session store.
Deploy the PHP classes, web routes, three modified views, shared partial/JS and all three
files in `assets/import-templates/` together. Existing packaged-inventory migrations must
already be applied, as required by the manual product form.

PHP needs `zip`, `SimpleXML`, `mbstring` and `mysqli` (present in the development XAMPP).
Set `upload_max_filesize` to at least 5M and `post_max_size` above 5M to allow multipart
overhead. Give PHP/proxy requests enough time for large imports and opening-stock posting.
No Composer or frontend dependency changes. Mobile/API controllers and /api/v1 routes
remain unchanged.

## Retained tests

Run from the repository root:

```powershell
C:/xampp/php/php.exe tests/workbook_import_smoke.php
C:/xampp/php/php.exe tests/inventory_workflow_smoke.php
node tests/workbook_import_ui_smoke.cjs
node --check assets/js/workbook-import.js
```

The import suite shadows all affected tables with connection-local MySQL temporary tables,
removes foreign keys only from those copies, uses synthetic fixtures and verifies real-table
fingerprints after dropping the copies. It tests the delivered XLSX files, missing required
values, bad units/prices/category paths, duplicate records, final-row rejection, sealed/opened
opening stock, rollback on closed financial periods, 1,000-row imports, formula/header/XML
rejections and permission checks. Temporary fixture files are removed; the test source stays.

Human-error coverage also includes malformed worksheet structures, prices entered as words,
negative or overly precise quantities, missing opening costs, zero package capacity, invalid
sale modes/groups, insufficient stock-adjustment permission and actual HTTP import retries.
The UI suite exercises changing files after validation, duplicate clicks, wrong formats,
oversized files, text-safe row errors, network failures, expired sessions and successful recovery.
